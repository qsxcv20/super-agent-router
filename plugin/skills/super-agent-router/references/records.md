# 实战记录（履历）

## 它是什么

成员**实际干成过什么**的记录。写在成员的方法论文件
`.superagent/methods/<成员名>.md` 的「实战记录」段。

与错题本严格镜像：

| | 错题本 | 实战记录 |
|---|---|---|
| 记什么 | 栽过哪（失败） | 做成过什么（成功） |
| 何时读 | 派工时前置给 Worker | 匹配时给 Router 参考 |
| 谁触发 | 复盘归因 | 验收通过后 |
| 作用 | 下次别再栽 | 下次派得更准 |

## 关键约束：执行者不可自证

**成就只能由「验收通过」触发，不能由成员自述触发。**

理由很直接：刚创建的成员写第一份履历时最不可信 ——
它还没被任何独立视角检验过。自述的履历不是履历，是自我吹嘘。

所以写入时必须提供 `verified_by`，且 **`verified_by` 不能等于 `agent`**。
这条由 `scripts/record-gate.mjs` 强制，不是靠自觉。

## 落地形态：写进方法论文件

**不另开 `records/` 目录。** 实战记录住在方法论文件里，理由：

1. Worker 读方法论时自然看到上次怎么做的 —— 不用再开一条注入通道
2. 方法论与履历同生共死 —— 方法论删了履历一起没，不留孤儿数据
3. 一处可版本控制、可 review、可分享

## 写入闸门（代码强制）

```
node scripts/record-gate.mjs '{
  "agent": "sa-chart-plot",
  "task": "月度对比图",
  "domain": "图表绘制",
  "approach": "先回显生效筛选条件，再出图并把口径写进图注",
  "evidence": "output/monthly.png，由 verifier 比对口径确认",
  "verified_by": "verifier"
}'
```

被拒的情况：

| 情况 | 拦它的理由 |
|---|---|
| 缺 `agent` | 不知道记谁的 |
| 缺 `domain` | 没有领域就无法用来判断匹配 |
| 缺 `approach` | 履历是索引不是流水账 |
| `approach` 超 300 字 | 写成流水账了 |
| 缺 `evidence` | 不可核验的成果不进履历 |
| 缺 `verified_by` | 没验收 = 自述 |
| `verified_by` 等于 `agent` | **执行者不可自证** |
| 方法论文件不存在 | 先写方法论，成果才有地方沉淀 |
| 该成员已达 20 条 | 只增不减的履历和只增不减的错题本一样致命 |

## 条目格式

```markdown
## 实战记录

### 2026-11-09 · 图表绘制 · 月度对比图
- 做法：先回显生效筛选条件，再出图并把口径写进图注
- 证据：output/monthly.png，由 verifier 比对口径确认
- 验收：verifier
```

## 闭环：履历如何影响匹配

```
任务到来
  └─ gate.mjs 读 roster.json 各成员的实战记录
        └─ 注入「实战记录（匹配参考）」段给 Router
              ↓
        Router 匹配时把这些当作「该派给谁」的参考
              ↓
        派工后 dispatch.mjs 把目标成员的记录带给 Worker
              ↓
        验收通过 → record-gate.mjs 写入一条新记录
```

## 履历不改归属声明

**实战记录只作参考，绝不自动改写 `roster.json` 的 `owns`。**

归属声明是人工可审计的资产。让模型根据战绩自行收窄 `owns`，
等于让系统自己给自己发权限 —— 不可审计，也不可追责。

所以：
- 注入时明确提示「归属仍以 roster.json 的 owns 为准」
- 想要收窄归属，由人改 `roster.json`，走 git 记录

## 与错题本的分工速查

| 场景 | 读哪个 |
|---|---|
| 派工时想知道「上次这类活栽在哪」 | 错题本的规则段 |
| 匹配时想知道「这人到底做成过什么」 | 实战记录 |
| 复盘时想知道「是不是同一类问题重复犯」 | 错题本 |
| 体检时想知道「这个成员是不是在虚胖」 | 实战记录条数 vs 错题本条数 |
