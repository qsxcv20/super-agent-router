# 复盘与错题本

## 分层：机制在插件，数据在项目

| 层 | 放哪 | 内容 |
|---|---|---|
| **机制** | 插件包 `references/review.md` + `scripts/lessons-gate.mjs` | 准入规则、归因表、条目格式、校验逻辑 |
| **数据** | 项目 `.superagent/lessons/<成员名>.md` | 实际教训条目，运行时增长 |

插件包是只读的，教训条目永远在项目里 —— 跨项目各看各的，不串味。

## 触发条件

只在以下情况复盘，**成功不复盘**：

- 任务失败
- 返工
- 被用户纠正

## 先归因，再动手

| 归因 | 症状 | 正确动作 |
|---|---|---|
| **范围不清** | 改了 scope 外的文件、问了不该问的问题 | 补 brief 的 scope 白名单 |
| **能力不足** | 方案平庸、反复试错 | 换更强模型 / 拆更细 / 建专项成员 |
| **工具缺失** | 卡在某个操作上绕路 | 补 skill / 装 MCP |
| **环境问题** | 依赖缺失、权限、路径不对 | 修环境，**不要动成员** |
| **需求本身有害** | 需求自相矛盾 | 停下来问人 |

**只有「范围不清」允许加约束。** 其余四类加约束都是错药。

## 错题本准入

算重大错误的四类：

- **越界** —— 改了 scope 外的文件、动了非授权资源
- **数据错误** —— 算错、写错、结论与证据不符
- **交付缺失** —— 声称完成但产物不存在，或未经验证
- **不可逆** —— 误删、误推送、误改线上配置

同型错误重复 ≥2 次（同类归因 + 同类根因）→ 无论单次严不严重都进错题本。

**不进错题本**：

- 一次性环境抖动 → 进 `incidents/` 原始记录，不提炼规则
- Router 自己的 brief 给错了 → Router 的锅，不甩给成员
- 需求本身自相矛盾 → 停下来问人

## 写入闸门（代码强制）

准入规则不靠自觉，由 `scripts/lessons-gate.mjs` 校验：

```
node scripts/lessons-gate.mjs '{
  "agent": "sa-spreadsheet-extract",
  "task": "月度对比图",
  "type": "数据错误",
  "symptom": "...",
  "cause": "...",
  "rule": "...",
  "next_time": "...",
  "occurrence": "single"
}'
```

被拒的情况：

| 情况 | 拦它的理由 |
|---|---|
| 类型不在四类内 | 一次性抖动不进错题本 |
| 归因指向 Router 自身 | 甩锅不是复盘 |
| 缺 `next_time` | 没有下次能执行的判断，条目无意义 |
| 规则是感想（"下次注意"） | 不可执行的规则等于没规则 |
| 该成员已达 15 条 | 只增不减的错题本和只增不减的约束一样致命 |

## 条目格式

```markdown
## 2026-11-09 · 任务「修登录超时」· 类型：越界
- 现象：改了 4 个文件，其中 `config/prod.yaml` 不在 scope 内
- 根因：brief 的禁止事项只写了否定式"不要改生产配置"
- **规则**：scope 必须写成具体路径白名单，禁止事项只作补充
- 下次派工：scope 未填具体路径清单时，不予派发
```

**"下次怎么办"必须是下次派工时能直接执行的一条判断。**

## 闭环：教训如何回到下一次派工

这是自我进化**真正生效**的环节，也是最容易断的一环：

```
复盘归因
  └─ 重大错误？ ──否──→ 不记
        │是
        ↓
  写 .superagent/lessons/<成员名>.md（过写入闸门）
        ↓
下次派工该成员时
  └─ PreToolUse(task) Hook 自动读错题本
        └─ 把「规则」段注入上下文
              ↓
        Router 把规则写进 brief 的 PRIOR_LESSONS 段
              ↓
        Worker 开工前就知道上次栽在哪
```

**只记不读 = 没进化。** 写错题本却不把它带回下一次派工，等于白记。

## 履历：成功侧的闭环

复盘只处理失败。**成功侧靠实战记录（履历）** —— 两者镜像：

| | 错题本 | 实战记录 |
|---|---|---|
| 记什么 | 栽过哪（失败） | 做成过什么（成功） |
| 何时读 | 派工时前置给 Worker | 匹配时给 Router 参考 |
| 谁触发 | 复盘归因 | **验收通过后** |

关键约束：**执行者不可自证**。`verified_by` 不能等于 `agent`，
由 `scripts/record-gate.mjs` 强制。自述的履历不是履历，是自我吹嘘。

写入位置是成员方法论文件的「实战记录」段，详见 `records.md`。

## 分层自治

| 改动 | 自动？ | 门禁 |
|---|---|---|
| brief 模板、路由表、错题本 | ✅ | 无（在项目里，git 可管可回滚） |
| 成员 `description`（能力声明） | ✅ | 只能增不能减，且同步 `roster.json` |
| 成员 `system_prompt` | ❌ | 只生成 diff，等用户确认 |
| 删成员 / 改账号级设置 | ❌ | 用户 |

## 周期体检

跑一次体检回答五个问题：

1. 有没有零调用的成员？→ 候选退休（标 deprecated，**先别删**）
2. 有没有能力重叠 >50% 的两个成员？→ 候选合并
3. `roster.json` 和成员实际 description 一致吗？→ 不一致必须修
4. 有没有成员的错题本条目超过 15 条？→ 先合并淘汰旧的才能加新的
5. 有没有成员被改过 prompt 后职责漂移？→ 拿快照比对，漂移就回滚

## 四种死法

| 死法 | 症状 | 对策 |
|---|---|---|
| 膨胀死 | 每次任务建一个 | 全局上限 + 单次上限 |
| 重复死 | 同义成员并存，派工时随机挑 | owns 去重 + 合并规则 |
| 劣化死 | prompt 越改越窄，成员被固化成只干一件事 | 约束预算 + description 可增可减 |
| 僵尸死 | 建了不用还占名额 | 定期体检 + 退休流程 |

**自我扩张的系统必须同时具备收缩能力。**
## Router 自己的错题本（v0.5.0）

错题本原本只属于**成员**。但归因表里明写着「Router 给错的 brief 是 Router 的锅」，
而错题本闸门会**拒绝**这类归因 —— 于是「Router 反复给错边界」这类错误**无处沉淀**，
只能靠单次记忆。

v0.5.0 起，项目里多一份 `.superagent/lessons/_router.md`：编排层自己的教训。
它与成员错题本同格式（契约 S1 的 7 字段模板），并由 SessionStart 注入 Router 上下文。

| 谁犯的错 | 记在哪 |
|---|---|
| 成员的执行失误 | `.superagent/lessons/<成员名>.md` |
| **Router 的锅**（brief 给错、边界没列全、模板各写各的） | `.superagent/lessons/_router.md` |

**归因先过 Router 自检**：任何要写进成员错题本的条目，先问一句「这是成员的锅吗」。
不是 → 别塞进成员账上。

## 履历的验收方必须真实存在（v0.5.0）

原先 `verified_by` 只校验「不等于 agent 名」，等于任何人都能填一个陌生名字写履历，
而履历会被注入给 Router 当匹配依据 —— 一次伪造就能影响路由。

v0.5.0 起，`record-gate.mjs` 要求 `verified_by` 在派工台账里存在一条
`agent == verified_by` 且 `state == 'done'` 的记录：确实有个叫这个名字的验收方跑过验收。
