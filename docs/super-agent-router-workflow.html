护栏的四层语义：凭什么说「拦得住」

判定对象不同 ⇒ 宽严不同。写类工具最严，读类最宽，复合工具另走一条。

层判定对象宽严规则
账号级 / 对外不可逆工具名 + 参数一律拦删成员、改成员、建号、部署上线、发布 Mini App —— 必须用户亲自发起
写类工具write / edit / bash / run_code严格目标路径必须精确落在 SCOPE 内；解析不出目标 ⇒ 兜底拒绝
读类工具read / glob / grep宽松允许读 SCOPE 所在目录树（展开子树）
复合工具run_code 内层调用只判危险作用域交回内层工具判定；不对自由文本扫路径（防误伤）
边界算不出—兜底拒绝解析不到 brief ⇒ 整段不受管控即视为不可信 ⇒ deny

时间线：这套东西是怎么长出来的

从 v0.3.0 到 v0.5.7 —— 不是设计出来的，是被 89 条缺陷逼出来的。

  1. v0.3.0 · 履历机制 + 目录整理

    方法论文件写入 + 注入参考不改 owns。仓库结构定型：plugin/ + .superagent/ + README。

  2. v0.3.1 · Hook 不触发的根因

    发现 hook 的 matcher 语义与激活时序有问题 —— 按官方契约补 SessionStart、省略 matcher。这一步之后机制才真正跑起来。

  3. v0.4.0 · 越界管控从君子协定变成代码

    发现按 session_id 查台账查错了维度：worker 查不到自己的 scope（管控整段失效），Router 反被套上 worker 的 scope。改成按子会话绑定。

  4. v0.5.0 · 契约单一事实源 + 静默失效清零

    建 references/contract.md（S1–S14），所有「解析不出就放行」的默认放行分支全部改成必然拒绝。

  5. v0.5.3 · 主 agent 管理层定位

    SessionStart 注入写明「你的定位是管理层，不是干活的」（契约 S12）。

  6. v0.5.4–v0.5.5 · 权限等级 + 自动审核

    引入 tier（scoped / full）、越界自动记账 → 父会话一条命令批准扩权；权威面脚本改为父会话专属。

  7. v0.5.6 · 并发与降级

    台账写入统一收口到锁内单入口（并发不再静默丢记录）；账号名单不可得时三态判定 + 降级披露。

  8. v0.5.7 · 公开分发

    家目录展开下沉到 absolutizePath()；空设备不再算写目标。加一键安装/卸载脚本、GitHub Release、MIT 许可。仓库转 public。

诚实边界

护栏是护栏，不是沙箱。这几条不能写成「绝对不可能」。

Hook ≠ 沙箱。worker 若能执行一段落盘的脚本，脚本内部的写入不受判定约束。真正的防线是运行时权限 + 审计留痕 + 验收复核。

提权不在被约束者手里。批准人必须是真实父会话 id，挡得住蓄意自提权，但挡不住有权限的人主动提权。

粒度有限。父会话不受 scope 约束 —— 「管理层定位」靠注入文本约定，代码不强制主 agent 不亲自上手。

粗筛会漏判。判据只认显式编排动词，机制讨论类提问（「错题库怎么持久」）不命中，只拿到一行兜底提示。
