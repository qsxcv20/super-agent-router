v0.3.2 → v0.4.0：把「派工记录」和「执行会话」拆成两层

v0.3.2 把这两件事当成同一个东西 —— 台账记的是发起方会话，而工具实际跑在子会话里。于是两头都错：worker 查不到自己的 scope（越界管控对真正要约束的人完全失效），Router 反而命中（被自己派出去的 worker 锁死）。v0.4.0 的全部改动，都是这一处错配的推论。

这一版是怎么被逼出来的

第一次真实跑完整闭环 —— 现场配置成员 → 派工 → 独立验收 → 记履历。

  1. 现场配置专项成员 sa-plugin-release先方法论 → 再建成员 → 再登记

    不是预置的，是这个任务来了才长出来的。

  2. 派工并产出

    升版清单 + CHANGELOG + 面向使用者的 README。worker 读不到自己的方法论，被拦了 4 次 —— 机制是断的，当场发现。

  3. 独立 verifier 首轮验收FAIL · 6/7 通过

    另查出 4 个问题：发布根本没落地（安装目录还是 0.3.2）、README 示例句打不中、miniapp 工具名不一致、watchdog 误伤交付报告。

  4. 修完收窄 brief 重派

    5 处修补 + 2 组新回归断言锁住行为。

  5. 复验PASS · 7/7

    安装目录与仓库逐字节一致（11 个脚本 differing=0），八套回归前后目录树哈希不变。

  6. 记履历闭环

    record-gate.mjs 把成果写进该成员方法论文件的「实战记录」段，verified_by = verifier，执行者不可自证。

最值得记的一条：三个问题是我自己没发现的，是独立验收查出来的 —— 包括那个高severity的「发布根本没落地」。验收环节不是走形式，是这套系统里唯一能抓到「我以为做完了」的东西。
