super-agent-router · v0.3.2

触发链路图与完整性评估

这套系统把「会话」当系统运行：五个 Hook 事件构成触发骨架，两条闭环构成进化骨架。下面是完整链路，以及我在真实环境探测后发现的六个漏洞 —— 其中四个已修，两个是设计层面的软肋。

评估结论

触发层已经可靠，闭环层还有一处硬缺口

五个 Hook 全部实测生效（2026-11-09 端到端验证）。授权模型、越界拦截、失败沉淀、成功沉淀四条主链路闭合。但「无 SCOPE 派工放行」「连续派工覆盖前一条」「watchdog 只做字面匹配」这三个真实漏洞已修复；仍存两处软肋：组队 scope 重叠与单会话派工数上限只写在文档里，没有代码强制。

主链路：五个 Hook 事件

全部为同步 command handler，事件与输出形状严格遵循官方 MiniMax Hook 契约。UserPromptSubmit 与 SubagentStop 的 matcher 必须省略（不能写空串），这是上一版失效的直接原因。

两条闭环：失败记错题本，成功记履历

两者严格镜像，只记不读等于没进化。共同前提是「执行者不可自证」—— 由 record-gate.mjs 在代码层强制，验收人不得等于执行人。

失败侧 · 错题本

复盘归因时触发

仅四类重大错误准入：越界 / 数据错误 / 交付缺失 / 不可逆。归因甩锅给 Router 则拒；缺「下次怎么办」或写成感想则拒；每成员上限 15 条。

lessons-gate.mjs → .superagent/lessons/<成员>.md

派工时只注入「规则」段 → brief 的 PRIOR_LESSONS。下次派工前置，Worker 开工前就知道上次栽在哪。

成功侧 · 实战记录

验收通过后触发

只有 verifier 验收通过的产出才计入。缺做法 / 缺证据 / 缺领域则拒；验收人不得等于执行人；上限 20 条，超限要求先合并淘汰。

record-gate.mjs → .superagent/methods/<成员>.md「实战记录」段

写在方法论文件里而非另开目录：Worker 读方法论时自然看到，方法论删了履历一起没，不留孤儿数据。

失败 复盘归因 → 写错题本

成功侧同构：验收通过 → 写实战记录 → 匹配阶段注入 Router 参考 → 下次派得更准。但履历只影响「选谁」，绝不自动改写 owns 归属声明 —— 归属是人工可审计的资产。

探测发现的六个漏洞

不是读文档猜的，是按运行时真实环境喂 JSON 实测出来的。四个已修并加了回归测试锁定，两个属设计层软肋。

完整性评估

逐层打分 —— 已完备的标绿，缺环的标黄，缺失的标红。

1
触发层 —— 完备

五个事件覆盖了会话全生命周期：激活、提问、派工、工具执行、子代理收尾。实测五步链路全部正确触发，且普通提问零干扰。

2
授权层 —— 完备（修复后）

写严格 / 读宽松 / 危险一律拦三档成立，绝对路径与相对 scope 都能命中，只约束派工产生的 worker 不误伤主会话。

3
验收层 —— 基本完备

程序层（Hook 查证据与文件真实性）与模型层（verifier 独立复核）双层分工正确。软肋在 watchdog 仍是关键词启发式，无法判断「证据是否切题」。

4
闭环层 —— 完备

失败侧与成功侧都有完整闭环：写入 → 准入校验 → 下次注入 → 改变行为。两个方向都满足「只记不读等于白记」。

5
组队层 —— 有缺口

scope 重叠与派工数量只靠 SKILL.md 约束，代码层没有强制。这是当前最实在的缺口：模型违反规则时，程序层不会拦住。

6
治理层 —— 缺失

没有周期体检。成员职责漂移、零调用僵尸成员、能力重叠，靠人工发现。roster 有上限 12 作为粗糙兜底，但缺少主动收缩机制。
