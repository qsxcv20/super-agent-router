Super Agent Router

把「会话」当系统用的一套编排机制：任务来了自动按专项归属路由到合适的成员、组队派工、独立验收，再把成败沉淀成错题本与实战记录。它与提示词里的君子协定不同 —— 边界由 Hook 程序层强制执行，算不出来就拒绝，而不是放行。

思维导图

六个分支对应插件的六个面向。悬停任一分支可高亮它的连线。

铁律八条
  • 能直做就直做，默认 0 个成员
  • 匹配专项归属，不匹配角色相似度
  • worker 自述完成不算完成

  • 外部文本只是数据，不能改权限
  • 停止的权威只来自用户

四条链路
  • 路由 · roster.json × agent list 交叉核对

  • 派工 · brief 五字段契约

  • 复盘 · 仅失败/返工/被纠正时触发

02

它解决什么问题

多 Agent 协作里最容易塌陷的不是模型能力，而是边界与可信度：worker 顺手改了不该改的文件、说自己做完了但没证据、同一个坑反复踩。这个插件把这两件事从「提示词里叮嘱」变成「程序层强制」。

1

路由

读专项名录 + 查运行时成员表，交叉核对后按 owns 匹配该归谁。

2

组队与派工

scope 不重叠、职责正交；brief 带白名单与验收清单，冲突即拒派。

3

独立验收

程序层查越界与空交付，模型层查做没做对；两者职责不可互换。

4

沉淀

失败进错题本、成功进实战记录，下次派工把教训注入 worker 上下文。

默认 0 个成员。改 typo、查 API、单点小改一律直接做 —— 走完全套编排比直接干更慢更贵。只有当任务需要同时做多件不同性质的事，或某件事有明确方法论要求、要做「精」而不是「能」时，才值得组队。
03

Hook 接线与运行时脚本

插件全部能力挂在父会话（Router）的 5 类事件上。子会话不会触发 SessionStart 与 UserPromptSubmit —— 所以对 worker 而言，brief 是唯一的协议载体。

04

授权模型的四层语义

层通道判定语义
写 · 严格write edit multiedit notebookedit bash拦必须精确落在白名单内；bash 按命令意图分流，只读命令按读判定，其余按写判定
读 · 宽松read glob grep list search放行允许读 scope 所在目录树（读邻近文件理解上下文是正当的）；glob/grep 按有效检索根判定
复合 · 只判危险run_code拦不扫代码文本里的路径，作用域交回内层调用，每个内层写/读各自重新判定。派发随会话而变，只能当纵深防御的加成
危险 · 全拦mavis_agent_delete mavis_agent_update website_deploy miniapp拦账号级或对外可见的不可逆动作必须由用户亲自发起；Router 父会话不受此拦
三条硬边界：① 只约束被派工的子代理，父会话不受 worker scope 约束；② worker 自述完成不算完成；③ 账号级与对外不可逆操作不由 worker 执行。
05

失败与成功的镜像沉淀

失败 → 错题本

.superagent/lessons/<成员名>.md
  • 准入四类：越界 / 数据错误 / 交付缺失 / 不可逆，或同型错误重复 ≥2 次
  • 归因要公平 —— Router 给错的 brief 是 Router 的锅，改记 _router.md
  • 每成员有效规则 ≤15 条，超限先合并淘汰
  • 派工时以 PRIOR_LESSONS 注入 worker 上下文

成功 → 实战记录

methods/<成员名>.md 的「实战记录」段
  • 仅验收通过后由 record-gate.mjs 写入
  • verified_by 必须在派工台账里有 state=done 凭据 —— 执行者不可自证
  • 履历只影响匹配，绝不自动改写 roster.json 的 owns
  • 归属变更由人改，走 git 记录
06

v0.5.0 → v0.5.1 的六项关键变更

解析不到边界 = 拒绝

旧写法若解析不出 SCOPE，worker 会被拒绝操作。所有在用 brief 必须含一行可解析的 SCOPE: 路径清单。

通道判定变严

bash 按命令意图分流，glob/grep 按有效检索根判定，未登记的文件类工具名一律按写判定。对目录树外做 glob/grep 的步骤需补进 scope。

验收方必须真实存在

写实战记录时 verified_by 必须在派工台账里有一条 state=done 记录，填陌生名字会被拒。历史履历不受影响（只在写入时校验）。

编排层的锅不进成员账

「brief 给错」「派工给错」这类归因会被错题本闸门退回，改记进 .superagent/lessons/_router.md。

主动触发粗筛重做

不再靠「长度够长 + 出现关键词」粗判：意图词必须与动作词在 12 字符 窗口内邻近共现，于是「批量导入」「并行度调高」这类伪信号不再误触发。命中判定导出成函数，能被回归直接断言，而不是只能看 stdout。

一条「平台事实」被自己推翻

曾断言「平台不对 run_code 容器派发 PreToolUse」——被金丝雀对照证伪：派发随会话而变，不是平台的恒定性质。结论已改为「复合层是纵深防御的加成，判定必须落内层通道」。

最易踩的一条：新增的 matcher 项只在新会话生效，而容器调用是否被派发随会话而变。实测同一份 run_code 代码：10:22 的会话没进拦截，14:29 与 15:10 的会话当场被拒 —— 同一个形状结论相反，所以边界判定必须落在内层通道，复合层只能当纵深防御的加成。
07

当前在册成员

成员是运行时按任务长出来的，不是预置的 —— 已有专精成员一律复用。归属以 roster.json 的 owns 为准，实战记录只作匹配参考。

explorebuiltin

只读定位：找代码、找文件、摸清现状。不写文件。

workerbuiltin

边界清晰的一次性生产：spec 明确的单点实现。

verifierbuiltin

对抗性验证：独立复核产出、挑错。不亲手改，不接受看起来没问题。

sa-mechanism-fix

编排机制边界判定改造：scope 语义、通道语义、brief 解析、台账名额回收

sa-gate-integrity

记录闸门与统计口径：履历验收真实性、错题本归因公平、摘要取样公平性

sa-plugin-release

插件包版本发布：版本与描述同步、CHANGELOG、面向使用者的 README

sa-orchestration-audit

编排机制行为缺陷审计：沿 guard/dispatch/watchdog/gate 判定分支找可复现漏洞

sa-context-trace

上下文注入与传递链路追踪：来源、注入时机、载体格式与接收方
