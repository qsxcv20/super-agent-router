## 一、这一版新增了什么

### 1. 零欠账收口（D-100~D-105）—— 台账自洽第一次有机器校验

**改了什么**

- **台账自洽有了 12 项机器校验**（`tools/ledger-check.mjs`）：索引表列数 /
  索引·明细·状态表**三集合相等** / 严重度分布 / 明细元信息行 / 明细条数 / 无重复 D 号 /
  **索引表必须是单块** / 状态词表（含「括注里不得出现第二个状态词」）/ 三处状态逐字相同 /
  状态统计 / 无「未修」条目 / 模板词表。任一项红 ⇒ 退出码非 0。
- **D-100 折行检测曾是死代码**：旧写法扫描起点写成 `blk.start`，而 `tableBlocks()` 产出的字段叫
  `startLine` ⇒ `undefined + n = NaN` ⇒「索引表被折行断成两块」这条检查**从来没执行过**。
- **D-103 台账条目模板不再留着旧词表**（`- 状态：已复现 | 推断`）—— 样板在教人写错，
  以后每条都会被照着写成词表外的值；模板已归一，并有专门检查守着。
- **D-105 台账明细状态行普遍是双结论**（「已复现（未修 —— 待派……）」把两个结论塞进一行），
  全表 **68 处**旧写法「未修 / 已修复」（该计数取自 **D-105 修复当时的中间快照**，现树已归一 ⇒ 不可在当前树上复现）⇒ 索引行说「已修」、明细行说「未修」也能六项全 PASS。
  现全部归一为契约词表内的**唯一结论**（103 条明细状态行），
  旧状态叙述**迁入各条「证据」字段**（不丢信息）。
- **D-104 后台任务三件套进了 hook 的读类 matcher**：`task_output` / `task_query` / `task_stop`
  —— 宿主 matcher 是**精确等值**匹配，`task` 不会顺带命中 ⇒ 这三个工具此前**完全不在**读通道判定里。
- **D-102 README 的「N 个脚本」字面量只查不比** ⇒ 改文档里的数字不会让任何检查报错；
  现由新增的 `tools/install-selftest/check-version-consistency.mjs` 逐字对账。
- **D-101 名额组去重没有直接断言**（原断言用的原派工是 `done`）⇒「追加轮被当成新的一份工作」
  这个退化抓不到；现补直接断言。

**为什么**

这一族的形态是「**注释宣称 ≠ 代码在做**」的工装版：台账自称自洽，但没有任何机器检查在盯 ——
索引表被折行断开、检查器自己算错、状态行塞两个结论，都不会让任何一条命令报红。
「零欠账」不是「欠的账都还完了」，而是「**以后欠了账，机器会立刻报出来**」。

### 2. 成员的持久身份口径（D-106~D-109）—— 持久层只放通用能力

**改了什么**

- **契约新增 S16**（硬规则 1~7 + 机器校验段 + 诚实边界）：成员的**持久层**
  （系统提示词 / 名录 / 方法论归属）**只放通用能力**；
  **一次性内容**（这次做哪几个实验、任务书路径、批次号、版本号、具体文件名）
  **一律由派工 brief 给**。
- **新增机器校验** `tools/member-identity-check.mjs`：判据表在本仓库**只有一份**
  （`FEATURE_SPECS` / `HOST_CONFIG_KEYS` / `DELEGATION_MARKERS` / `PATH_EXEMPTIONS`）。
- **判据口径**（契约是唯一事实源）：
  - front matter 里**只有 description 参与判定** —— 宿主配置字段（如 `defaultWorkspaceDir`）不参与；
  - 「由 brief 决定」这类**让渡句不算残留**，但让渡句里的**具体标识照判**；
  - 具体标识覆盖**脚本 / 配置文件名**与**带目录段的相对路径**；
  - 仓库相对引用、方法论 / 错题本路径、**仓库自有资产**（裸文件名且在仓库内确实存在）豁免。
- **D-107 检查器的两处误报修掉**（把宿主配置字段与合规让渡句判成残留 ⇒ 真实目录 14 处命中全是误报
  ⇒ 存量整改做对了仍然报红 ⇒ 这道闸门会被当成噪声忽略）。
- **D-108「未知 front matter 键按 fail-closed 处理」补上专属断言**。
- **D-109「仓库自有资产」豁免越界修掉**（豁免只给裸文件名，实现却按「末段同名」判定
  ⇒ 带目录段的相对路径被静默放过）。
- **建员闸门补三条**（`references/bootstrap.md`）：提示词正文不含本次任务细节 /
  不出现工作区路径 / 方法论「适用」段写能力适用场景。

**为什么**

成员的提示词与名录是**持久层** —— 一次任务做完它还在那儿。
把「这次做哪几个实验」写进去，它会**长期留在**所有后续任务的上下文里，
下一个读成员的人会把它当成这个成员的固有属性。更麻烦的是它**看不出来**：
提示词里混进一个盘符路径或一个具体文件名，肉眼扫过去完全正常 ——
不像代码有测试、像文档有 review。

### 3. 版本与结构数字终于有常驻断言（D-94 / D-102）

新增常驻自测 `tools/install-selftest/check-version-consistency.mjs`（**12 条断言**）：
「当前版本」在 manifest / 两份 README / CHANGELOG 顶部**四处一致**，
且根 README 的**目录结构数字**（handler 数 / 脚本数）**与实际文件对账**
（数字从文件算，不从 README 抄）；缺失或不一致即退出码非 0。

**为什么**：以前「版本号四处一致」**没有任何自动化断言守护**（`check-readme-consistency.mjs`
读了版本号却只打印不判定）；同类漂移真的发生过（根 README 的「7 个 handler / 13 个脚本」
与实际不符），靠人眼在发布前才发现。

**顺带修了一处会复发的假红（D-110）**：这条断言的「造故障」手法原先把版本号**写死**在测试里
⇒ 每次升版都成**空操作** ⇒ **造故障的手法自己坏了**而断言假红；现改为**从当前版本派生**，
并在每次注入后**断言字节真的变了**（详见第五节）。

## 三、诚实边界（本版**没有**做到的事，别当成已覆盖）

1. **本批没有取到新的活体 hook 拦截证据** —— 活体证据**仍然只有 D-97 那一轮**
   （内层 `bash` 重复调用形态）。本版只核了 `hooks.json` 的 matcher 与回归断言，
   **没有**主张活体已验证，也不把「回放正确」写成「活体已验证」。
2. **成员身份检查器是词法级判据** —— 只保证「已知的这几类残留一定被报出来」，
   **不保证**持久层里没有用**别的措辞**写的任务内容。
3. **检查器只覆盖本机已存在的成员文件** —— 账号目录不可用时只查名录
   （退出码 0，但结论行明写「账号级未检查」）；该形态只在夹具层验证过，未在真机复现。
4. **`defaultWorkspaceDir` 不判** —— 它把成员钉在哪个项目属于**项目归属**问题，
   校验器不判它；一个专为一单建的成员仍可能带着那一单的工作目录。
5. **新建成员时的提示词写法，机器校验管不了** —— 它只管**已经建出来的**成员文件；
   提示词写没写对，仍由建员者与独立验收把关。

> 第 1~4 条是本轮 brief 指定的四条；第 5 条出自独立验收报告的 D 组（5 条诚实边界，照录且未越界）。
> 本单**没有**把它省掉 —— 少写一条就是「少说一条边界」。

**另外两条不属于本版、但仍开着的**（不因本次发布而闭合）：
**D-92 派工粒度（S4.6）仍无代码兜底**（只读类派工不触发组队冲突闸门，靠派工方遵守）；
**闸门只覆盖「严格连续」这一族**，被别的调用打断的打散形态覆盖有限。

## 五、发布前自查发现并已修复：全量回归曾有 1 条红（D-110）

**如实交代，不粉饰**：上一轮升版时，全量回归确实有 1 条红（D-94-D6）。
本段保留当时的发现与证据；**结论已闭合** —— 终稿树现在是
**16 套 / 1051 条断言 / 0 FAIL**（exit=0）。

- **现象（修复前）**：红的是 `tests/zero-debt-test.mjs` 的
  `D-94-D6 plugin.json 升版而文档没跟 ⇒ 退出码非 0 :: exit=0`。
- **根因**：`tests/zero-debt-test.mjs:413` 写死了
  `man.replace('"version": "0.5.10"', '"version": "0.5.11"')`。
  manifest 升到 0.5.11 后，这句 replace 变成**空操作**（一个字节都没改）⇒
  造出来的「假仓库」里 manifest 与文档仍然一致 ⇒ 校验器 exit=0 ⇒ 断言红。
  **红的是测试工装里写死的版本字面量，不是本版的功能**；全仓代码里
  `"version": "0.5.10"` 的硬编码**仅此一处**。
  更深一层：**造故障的手法自己坏了** —— 这不是偶发，**每次升版都会复发**
  （把写死的版本号再改一次，只是把同一个坑推迟到下次升版），
  与 D-100「折行检测是死代码」同族（检查静默失效）。
- **实测对照**（跑在 `%TEMP%` 下的临时假仓库里，真实仓库一个字节未动）：

  | 写法 | 替换是否真的改了字节 | 校验器退出码 |
  |---|---|---|
  | 基线（未改动副本） | —— | exit=0 |
  | 硬编码 `0.5.10` → `0.5.11` | **否**（空操作） | exit=0 |
  | 派生（`0.5.11` → `0.5.12`） | **是** | **exit=1** |

  派生写法下 6 条断言按预期转红（根 README 的「当前版本」/「本插件当前是」、
  plugin/README 的两条、CHANGELOG 的最新发布段标题、CHANGELOG 里有本版本段）——
  说明这组断言本身有效，红的只是**喂给它的变异没生效**。
- **修法与现状（已闭合）**：该缺陷已登记为 **D-110**（工具层 / P2），由 **sa-mechanism-fix** 修完，
  父会话独立复跑确认。修法两条规矩**缺一不可**：
  ① 版本号**从假仓库 manifest 派生**（读当前版本 → 末段 +1），任何地方都不写死版本号；
  ② 每次注入都**断言字节真的变了** —— 没变就是手法失效，当场停下并报「造故障的手法失效了」，
  而不是让后面的断言语焉不详地红。
  配套 **5 条专属断言**（派生 1 条 + 注入字节自检 4 条）与 **2 个专属语义变异体**
  （派生写法改回写死 ⇒ 只红 `D-110-D1`；替换退化成空操作 ⇒ 只红 `D-110-D2`），矩阵 **MISS=0**。
  **终稿树实测：16 套 / 1051 条断言 / 0 FAIL**（exit=0）——
  零欠账套件由 61 条变 **66 条**（改前的 61 条取自**当时的中间快照** —— `tests/zero-debt-test.mjs` 是本版新增文件、git 里无基线可比），其余 15 套一条没动（合计 985 条）。
- **对本版功能的影响**：无。v0.5.11 的三项变更各自的机器校验
  （`ledger-check.mjs` 12 项 / `member-identity-check.mjs` / `check-version-consistency.mjs` 12 条）
  全部通过；`check-readme-consistency.mjs` 144 PASS / 0 FAIL；
  安装脚本自测 8 套件 / 343 条 / 0 FAIL。
