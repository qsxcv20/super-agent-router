## 一、判据分三档

| 档 | 含义 | 期望 |
|---|---|---|
| **A 编排意图** | 用户在要求「拆 / 分 / 并行 / 派谁 / 验收」这类需要编排的动作 | **必须命中**（注入路由指令） |
| **B 单点动作** | 改 typo / 查文档 / 加注释 / 修 bug —— 一件事一个人做完 | **必须不命中**（静默） |
| **C 伪信号** | 出现「同时 / 多个 / 分别 / 各自 / 批量 / 并行」等词，但**不是**在要求编排 | **必须不命中**（静默） |

C 档是本次修复的重点风险：原实现靠 `prompt.length > 40` 才让 SIGNAL 生效，
去掉长度门槛后如果不做「动作性」限定，`批量导入`、`分别说明`、`多个分支` 这类普通句子会被误触发。

## 五、机制判据（不只是语料）

1. **判定函数可独立断言**：命中判定必须从 `plugin/scripts/gate.mjs` 抽到 `plugin/scripts/lib.mjs` 并 `export`，
   回归能 `import` 后直接喂样本断言 —— 不允许只能靠「跑脚本看 stdout」来验证。
2. **载荷解析失败不静默**：gate 必须用严格解析；载荷为空或非法 JSON 时，**不能**静默退出，
   要留下可查痕迹（至少一条记录到可写位置），且**不得**因此注入编排指令。
3. **条件式兜底注入**：未命中时，若「roster 存在 + 有专项成员 + 该成员有实战记录」，
   允许注入**一行**极短提示；不满足条件时**必须 0 字节输出**（单点小改零噪声）。
4. **兜底不改变归属**：兜底提示只能影响「该考虑谁」，不得改写 `owns` 归属声明。
