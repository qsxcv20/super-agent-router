# 缺陷台账自洽检查（可复跑）

- 工具：`tools/ledger-check.mjs`（检查器）、`tests/ledger-test.mjs`（回归套件）
- 对象：`docs/audit/defect-ledger.md`（**父会话的资产**，本工具只读不改）
- 背景：v0.5.6 独立复验的 **F-03** 判 FAIL —— 台账的「统计行」与「明细区」对不上。
  复验方亲手回退/改坏台账实测过：① 索引表某行含**未转义竖线**（`mavis agent delete|update`），
  严格解析按 `|` 切列把那一行切成 8 列而不是 5 列 ⇒ 那行被丢弃 ⇒ 索引表比明细区少一条；
  ② 有明细段缺「来源/严重度」行 ⇒ 明细区**根本算不出**统计行那个分布。
  统计行自己写着「统计以本表逐条明细为准」—— 做不到那句话，就是账不实。
- 与旧脚本的差别：父会话原来的 `docs/audit/.tmp-parent/ledger-check.mjs`
  ① 放在 **gitignore 的临时目录**里（第三方无法复核「谁在什么口径下跑的」）；
  ② 解析**宽松**（用宽松正则挑行）⇒ **恰恰漏掉了上面第 ① 类问题**。
  本工具严格解析，并进版本库。

## 1. 怎么跑

```
# 只看台账自不自洽（人读的输出，退出码 0 = 自洽）
node tools/ledger-check.mjs

# 机器可读
node tools/ledger-check.mjs --json

# 回归套件（基线 + 变异体）—— 这套已进 node tools/run-tests.mjs --all
node tests/ledger-test.mjs

# 只跑变异体（证明这套断言不是恒绿）
$env:SAR_MUTATION_LEDGER='1'; node tests/ledger-test.mjs
```

台账不在仓库里时（例如只装了插件包），给检查器一个文件路径：
`node tools/ledger-check.mjs <文件>`（变异体检查就是这么用的）。

## 2. 口径（判据写在这里，改口径 = 改判据，必须显式改这里）

| # | 检查 | 判据 |
|---|---|---|
| 1 | `index-columns` | 严重度索引表的**每一行必须正好 5 列**。切列按 Markdown 规则：**未转义的 `\|` 是列分隔符，`\|` 是字面竖线**。多一列就报出**行号 + 该行内容** |
| 2 | `sets-equal` | **三个 D 号集合完全相同**：① 严重度索引表、② 明细段标题、③ 修复状态表。明细段只认「## 三、缺陷明细」**之后**的 `### D-xx`（第二节模板代码块里的 `### D-01` 不算）；「修复状态表」= 所有**表头含「状态」**的表的**并集**（台账按修复轮分了好几张表，单独任何一张都不是全集）。差一条就报出是哪条 |
| 3 | `severity-distribution` | 从**明细段自己的**「来源：… ｜ 严重度：Pn ｜ 归属层：…」行**重算** P0/P1/P2/P3，与**统计行**的 `P0 N 条、P1 N 条…` **逐字**比（不给容差、不看索引表）。统计行的数字不能反过来当严重度来源 —— 那是拿结论证明结论 |
| 4 | `detail-meta-line` | 每条明细段都要**有**一行「来源：… ｜ 严重度：Pn ｜ 归属层：…」。严重度字段允许带括号说明（如 `P0（原判 P1 …）`），但三个字段必须齐全 |
| 5 | `detail-count` | 明细区条数 = 统计行的「总计 N 条」 |
| 6 | `no-duplicate-d` | 同一张表里同一个 D 号**不得出现两次**（两次 = 两个互相矛盾的状态）。这是第 2 条的补充：集合相等但行重复，状态照样自相矛盾 |

## 3. 变异体（每个都必须让目标检查转红）

| 变异体 | 改坏什么 | 目标检查 |
|---|---|---|
| M1 | 索引表某行塞进**未转义竖线**（F-03 第 ① 类问题的阳性样本） | `index-columns` |
| M2 | 删掉一条明细段的「来源/严重度/归属层」行 | `detail-meta-line` |
| M3 | 把统计行的 P1 数字改坏 | `severity-distribution` |
| M4 | 删掉索引表里的一个 D 号 | `sets-equal` |
| M5 | 状态表里给一个 D 号补一行**状态矛盾**的重复行 | `no-duplicate-d` |
| M6 | 把一条明细自己的严重度改掉 | `severity-distribution` |

变异全部在**系统临时目录的副本**上做 —— 真实台账从头到尾一个字节都不改
（套件里有一条断言专门盯这件事：「变异过程中真实台账逐字节未变」）。

## 4. 已知缺口 —— **已闭环（父会话修）**

**这三处是怎么被发现的**（留档：免得下一版以为「台账天生自洽」）：
本工具是 v0.5.6 独立复验 **F-03 判 FAIL** 之后才有的。当时台账有两类不自洽 ——
① **统计行与明细区对不上**（复验方亲手测的）：索引表有一行含**未转义竖线**，
严格解析按 `|` 切列把那一行切成 8 列而不是 5 列 ⇒ 那行被丢弃 ⇒ 索引表 88 行 vs 明细区 89 条；
另有 7 条明细段缺「来源/严重度」行 ⇒ 明细区**根本算不出**统计行那个分布；
② 本工具跑出来的三处（其中 `detail-meta-line:D-81` 是**同一个病**的另一种形态：
「来源/严重度」那一行被放在了**文件末尾**，脱离了自己的明细段）。

| 缺口 | 现象 | 根因 | 父会话的修法 | 状态 |
|---|---|---|---|---|
| `detail-meta-line:D-81` | 明细段 D-81 没有「来源/严重度/归属层」行 | 那一行被放在**文件末尾**（脱离了自己的明细段） | 移回 D-81 段内（现第 1338 行） | **已修** |
| `severity-distribution:P2` | 明细重算 P2 = 30，统计行写 31 | 上一条连带 | 同上（归位后自动转绿） | **已修** |
| `no-duplicate-d:D-75` | 状态表里 D-75 两行，状态**互相矛盾**：「已修（待独立复验）」 vs 「口径已定，待实现」 | 合并时漏改 | 合并成一行（保留「已修（待独立复验）」那行） | **已修** |

父会话另按本文件 §5 的「其它发现」改了口径：① 「本轮新增」改成 **D-44~D-85 共 42 条**；
② 章节编号统一为**一~九**（原来有两个「六」，且「六」排在「五」前）；
③ 状态表标题改成「**本轮新增 D-44~D-85** 的修复状态（待复验）」（原来写「34 条」与表内容对不上）。
§5 第 4 条（状态表行序乱）**未改**：只影响可读性，不影响集合口径，留给下一版。

**判据口径（机制保留，清单已清空）**：偏差集合必须是 `KNOWN_GAPS` 的**子集** ——
出现清单之外的**新偏差立刻转红**；清单里的缺口若被修好（不再出现），套件打印
`WARN ... 请把 KNOWN_GAPS 里对应条目删掉`（**不转红**，不误伤回归）。
**本清单当前为空**（三处缺口已闭环，按这条规矩删掉，不留「已修但仍挂着」的假账）。
以后台账再不自洽时，把新偏差登记进来（key + why + fix）即可 —— 不登记的一律转红。
