# sa-gate-integrity

## 归属

把**履历、错题本、专项名录**这三道记录闸门的判定与统计口径做实：
验收方必须真实存在、归因公平要拦得住各种语序、记录可见性不能因为排在名录后面就消失、
段首定位不能混用口径。产出的改动让「写进记录的东西可信、可查、不可伪造」。

## 适用

- 缺陷台账里属于 `record-gate` / `lessons-gate` / `records` / `roster` 的判定缺陷
- 「履历可以被任何人伪造」「Router 的锅能写进成员错题本」「靠后的成员记录看不见」这类问题
- 记录条数上限算错、段首定位算错

## 不适用

- **guard / lib / dispatch / watchdog / session-start** 的判定逻辑 —— 归 `sa-mechanism-fix`
- 不改协议文档与参考手册（`references/`）—— 契约由父会话维护
- 不做版本发布、不推送远端、不改 `plugin/scripts/` 之外的机制脚本

## 方法

1. **先读契约**：`plugin/skills/super-agent-router/references/contract.md` 的 S1、S7、S9 是唯一依据。
2. **再读缺陷台账**：`docs/audit/defect-ledger.md` 里 `D-` 编号中归属本专项的条目。
3. **先写清楚「真实」怎么判定，再写代码**。例如 `verified_by` 的真实性，
   判据是「派工台账里存在 `agent == verified_by` 且 `state == 'done'` 的记录」，
   这条判据必须写在代码注释里，让后来者知道为什么不是「名字不等就行」。
4. **归因公平正则要按语序枚举，而不是按词枚举**：把可能被指控编排层的表达方式列全，
   再逐个确认能被拦到。改完要用**真实语例**跑一遍（见验收清单）。
5. **统计口径要能被验算**：条数上限、摘要取样条数这类逻辑，
   要能用一组具体输入算出具体结果，不能只靠「读起来对」。
6. **改动要向后兼容**：已有的错题本、已有成员的履历不能因为改动而读不出来。

## 验收清单

- [ ] `verified_by` 校验的是「验收方真实存在」，不是「名字不等于 agent」
- [ ] 归因公平检查能拦住的语序至少包括：`brief 给错`、`给错的 brief`、`派工给错`、`Router 的锅`
- [ ] 用真实语例跑过归因闸门：Router 归因被拒、成员自身失误被放行（两种情况都要有回归断言）
- [ ] 记录摘要的取样不再按名录顺序截断，排位靠后的成员不会被结构性隐藏
- [ ] 段首定位口径统一，同一文件内不再混用相对偏移与绝对索引
- [ ] 已有错题本与已有履历在改动后仍能被正确读出
- [ ] 记录类回归全绿（`records-test` `lessons-test` `roster-test`）
- [ ] 只改动 SCOPE 内的文件

## 易错

- 把归因公平写成「匹配一个关键词」——换个语序就漏，必须按语例枚举并回归
- 改 `verified_by` 校验时忘了考虑「历史履历里已写入的 verified_by 不是台账里的 agent」会读不出来
- 改摘要取样时把上限从「前 6 名」改成「前 6 条记录」，粒度搞错
- 只改 `records.mjs` 的取样却没改 `session-start.mjs` 与 `gate.mjs` 的调用方，摘要口径仍然不一致
- 归因闸门拦得太狠，把成员自己的真实失误也拦掉了——闸门要拦甩锅，不是拦认错
